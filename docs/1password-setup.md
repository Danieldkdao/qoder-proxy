# 1Password, Docker and Hermes on the Mac Mini

This setup loads secrets from a **1Password Environment**. It does not create or read an application `.env` file. Run these commands on the Mac Mini, including when connected from the MacBook Air over SSH.

## 1. Create the environment

1. Sign in to [Qoder Integrations](https://qoder.com/account/integrations) and create a Personal Access Token. This is an account-issued credential, not a random password. Requests consume your Qoder account's credits and model access.
2. In the 1Password Mac app, open **Developer → View Environments → New environment**. Name it **Qoder Proxy**.
3. Add these secrets:

| Name                          | Value                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| `QODER_PERSONAL_ACCESS_TOKEN` | The actual token generated by Qoder                                                  |
| `PROXY_API_KEY`               | A separate strong password generated by 1Password; use at least 32 random characters |
| `DASHBOARD_ENABLED`           | `false` for initial setup                                                            |

4. Open **Manage environment → Copy environment ID**. The ID identifies an environment; it is not the PAT. Never paste the PAT or proxy key into chat or Git.
5. Enable the 1Password desktop app's CLI integration in its Developer settings. `op --version` should work. The app may require unlocking/authorization on the Mini. SSH access to the Mini does not automatically authorize 1Password CLI.

If you need unattended authentication, use a separately provisioned 1Password service account scoped to this Environment. Its bootstrap credential belongs in your host's protected credential mechanism, not this repository or the Docker container. `OP_SERVICE_ACCOUNT_TOKEN` is never forwarded into this container. A desktop-authorized session is the recommended initial setup.

Sources: [1Password Environments](https://www.1password.dev/environments), [op run](https://www.1password.dev/cli/reference/commands/run), [Qoder authentication](https://docs.qoder.com/cli/authentication).

## 2. Fill the package-script templates

Every public command in `package.json` has this form:

```text
op run --environment ENVIRONMENT_ID -- node scripts/tasks.mts TASK
```

This checkout is configured with Environment ID `umcywiy3b7hzpi2ln4zqrcywi4` in every package script. If you use another Environment later, replace that ID in each command; `ENVIRONMENT_ID` in the example denotes the template. The ID may be committed; the secret values must not be. Keep `--no-masking` absent. `op run` loads variables directly from the Environment and keeps its normal output masking enabled.

The underlying task entry point also exists for secret-free CI, container builds and automated tests. CI invokes it directly so it does not require access to your 1Password account. It is not an alternate source of secrets. Runtime startup still requires a valid PAT and proxy key.

## 3. Build and start

```sh
cd ~/Desktop/qoder-proxy
npm ci
npm test
npm run docker:build
npm run docker:start
npm run docker:status
```

`docker:start` creates the managed container `qoder-proxy`, published only at **127.0.0.1:3000**. It refuses to overwrite an unrelated container with the same name. The default image is `qoder-proxy:local`.

Test authenticated Qoder inference and a function-call/result/final-answer exchange:

```sh
npm run proxy:check
```

This makes real model requests and consumes Qoder credits. A healthy `/health` endpoint alone does not prove the PAT or model is authorized.

## 4. Connect Hermes and verify actual tool execution

```sh
npm run hermes:test
```

This launches the **installed Hermes CLI** with an isolated temporary profile. Hermes connects to the proxy, asks Qoder to use its terminal tool, writes a random marker into a temporary proof file, consumes the tool result, and returns a final answer. The script checks both the file and answer, then removes the temporary profile/workspace.

The test uses Hermes's one-shot mode, which auto-approves tools. Its prompt is fixed to creating and reading that temporary proof file. It does not run the test in your project checkout. The acceptance profile receives only the proxy API key; it does not receive the Qoder PAT or 1Password service-account token.

The separate non-secret profile is already configured on this Mini. To prepare it explicitly on another checkout:

```sh
npm run hermes:configure
```

For normal chat:

```sh
npm run hermes:chat
```

The first invocation creates a dedicated, non-secret config at `~/.hermes-qoder-proxy/config.yaml`. It uses `provider: custom`, model `auto`, the loopback proxy URL, and `key_env: PROXY_API_KEY`. It does not save the key in YAML and does not replace your existing Hermes configuration. Future chats use that separate profile, with its own history. Existing profile configuration is preserved.

To use an existing Hermes profile manually, add a custom Chat Completions provider with:

```yaml
model:
  provider: custom
  default: auto
  base_url: http://127.0.0.1:3000/v1
  key_env: PROXY_API_KEY
  context_length: 64000
agent:
  reasoning_effort: false
```

Launch that profile from `op run --environment ENVIRONMENT_ID -- hermes` so the key exists only in the process environment. Do not pass `--api-key SECRET` or paste the PAT into Hermes. The PAT authenticates the proxy to Qoder; the proxy key authenticates Hermes to the proxy.

Some CLI options and model capabilities are intentionally unsupported; see README.md. Keep unsupported auxiliary tasks, image input and embeddings on another provider. Model adherence to the emulated tool protocol still needs a real account/model acceptance test.

## 5. Stop, reload secrets, or recover after reboot

```sh
npm run docker:stop
npm run docker:start
# Or, when the managed container already exists:
npm run docker:restart
```

`docker:restart` **recreates** the managed container and injects fresh secrets from 1Password. Editing a value in 1Password does not change a running process. After a PAT rotation, recreate the container. After rotating `PROXY_API_KEY`, restart your Hermes process too.

Docker automatic restart is deliberately disabled for this workflow. Secret values exist only in process memory and are not saved in container configuration. A plain `docker start`/`docker restart` cannot restore them; the bootstrap fails closed without fresh input. After restarting Docker or the Mini, use `npm run docker:restart` with authorized 1Password access. Do not add `--restart unless-stopped` without also implementing a host-side authenticated supervisor.

Emergency stop without a fresh 1Password authorization is available as `node scripts/tasks.mts docker:stop`. It only removes a container bearing this project's management label.

## How secrets reach Docker

```text
1Password Environment
  → op run (masking enabled)
  → allowlisted runtime payload in host process memory
  → Docker attach stdin (no secret command-line arguments)
  → container bootstrap process.env
  → delayed import of the HTTP server
  → isolated Qoder CLI receives only its PAT and required runtime settings
```

Unlike `docker run -e TOKEN=value`, this path does **not** put the PAT, proxy key or dashboard password in Docker's saved `Config.Env`. It does not write an env file, bake secrets into the image, mount your home directory, or mount the Docker socket inside the container. The container runs as `node`, with a read-only root filesystem, temporary RAM-backed `/tmp`, dropped capabilities and no-new-privileges.

The Docker daemon, host administrators and privileged debuggers are still trusted: they can access a running process's memory or execute code in the container. This is not an encrypted enclave. Secret values live in the proxy/Qoder process memory for their required lifetime, even after `op run` exits. Host swap, crash diagnostics and privileged debugging remain OS-level concerns.

Build/test/format subprocesses are run with a minimal non-secret environment. The Docker CLI is also given a minimal environment; the 1Password service-account credential is not inherited. Prompt logging is off by default, and the browser does not receive the proxy key. Never use `printenv`, `docker exec ... env`, shell tracing (`set -x`) or `--no-masking` to debug a real token.

## Environment variables in detail

Only the first two variables are required for a working private deployment. Keep the initial defaults for everything else unless a specific need arises. Values in 1Password are strings; boolean switches use the exact strings `true` and `false`.

### Credentials and dashboard access

| Variable                      | Meaning, default and guidance                                                                                                                                                                                                                   |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `QODER_PERSONAL_ACCESS_TOKEN` | **Required secret.** Issued by Qoder under Account Integrations. Used by the CLI to access your Qoder account. Revocation, expiration, credits and plan/model access affect inference. Never use a generated password in its place.             |
| `PROXY_API_KEY`               | **Required secret.** A separately generated random key. Hermes sends it as a Bearer header to this private proxy. It is not a Qoder credential and must not equal the PAT. Rotating it requires recreating the container and restarting Hermes. |
| `QODER_API_KEY`               | Legacy alias for the PAT, supported for compatibility. Prefer `QODER_PERSONAL_ACCESS_TOKEN`; it wins if both are set. Do not create a second, different secret here.                                                                            |
| `DASHBOARD_ENABLED`           | Source default `true`; the secure launcher sets it to `false` when no dashboard password is supplied. Recommended initial value: `false`. Set `true` only with a password.                                                                      |
| `DASHBOARD_PASSWORD`          | Optional secret. Required to log into the dashboard if enabled. Generate a third independent password. Never reuse the PAT or proxy key.                                                                                                        |
| `DASHBOARD_SECRET`            | Optional secret signing key for sessions. Defaults to a fresh random value in memory. You normally can omit it. Sessions are server-side and are revoked on restart/logout even if this key is stable.                                          |
| `SECURE_COOKIES`              | Default `false`, appropriate for the loopback HTTP dashboard. Set `true` when accessing the dashboard over HTTPS; browsers will not send a Secure cookie over ordinary HTTP.                                                                    |

### Inference limits and resource use

| Variable                  | Meaning, default and guidance                                                                                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `QODER_TIMEOUT_MS`        | Default `120000` (two minutes). Maximum active CLI generation time, excluding queue wait. Timeout terminates the process group and escalates termination if needed. Increase only for models/prompts that need it. |
| `QODER_MAX_CONCURRENCY`   | Default `1`; allowed 1–32. Number of simultaneously running CLI requests. One is a good starting point on the Mini because each process can spike memory/CPU.                                                      |
| `QODER_MAX_QUEUE`         | Default `8`; allowed 0–1000. Requests allowed to wait for a worker. `0` rejects immediately when busy. An excess request receives 503 rather than starting another process.                                        |
| `QODER_QUEUE_TIMEOUT_MS`  | Default `30000`. How long a queued request may wait before returning 503. Independent of active-generation timeout.                                                                                                |
| `QODER_MAX_OUTPUT_TOKENS` | Default `16k`; only `16k` or `32k`. The CLI's coarse default output budget. Larger values may consume more credits and memory. This is an output budget, not a context-window size.                                |
| `MAX_PROMPT_BYTES`        | Default `2097152` (2 MiB). UTF-8 size cap on the serialized prompt, including full history and tool schemas. Too-large input is rejected, not silently truncated. This is bytes, not tokens.                       |
| `MAX_OUTPUT_BYTES`        | Default `4194304` (4 MiB). Combined CLI stdout/stderr cap. An excessive output terminates the request to bound memory use.                                                                                         |

### Network and runtime settings

| Variable                | Meaning, default and guidance                                                                                                                                                                                              |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HOST`                  | Native server default `127.0.0.1`. The image sets `0.0.0.0` **inside** the container so Docker port publishing works. Not forwarded from 1Password into Docker; the host-side published address remains loopback.          |
| `PORT`                  | Native default `3000`. The secure container uses internal port 3000. To change the Mac's listening port, set `QODER_HOST_PORT` instead. Not forwarded into Docker.                                                         |
| `QODERCLI_BIN`          | Native default `qodercli`. The image pins `/usr/local/bin/qodercli`. Useful for a native custom installation; not forwarded from 1Password into Docker.                                                                    |
| `PUBLIC_BASE_URL`       | Default unset; the dashboard uses its browser origin. Optional canonical **server origin**, such as `https://proxy.example`, without `/v1`. It changes displayed links, not bind addresses or routing. Omit for local use. |
| `CORS_ORIGIN`           | Default disabled. Optional browser origin allowed to call the API. Hermes is a server/CLI client and does not need CORS. CORS is not authentication or a network firewall.                                                 |
| `ALLOW_UNAUTHENTICATED` | Direct-server escape hatch, default `false`. The secure 1Password/Docker launcher intentionally does not forward or accept it; a real proxy key is mandatory. Leave unset.                                                 |
| `NODE_ENV`              | Image sets `production`; it is not a secret. The launcher does not forward it from 1Password.                                                                                                                              |

### Logging

| Variable             | Meaning, default and guidance                                                                                                                                                    |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOG_PAYLOADS`       | Default `false`. If explicitly enabled, request bodies may be retained in the bounded RAM log and can contain code or user-supplied sensitive data. Keep `false` for normal use. |
| `LOG_MAX_ENTRIES`    | Default `500`; allowed 1–10000. Maximum entries per in-memory log buffer. Restart clears them.                                                                                   |
| `LOG_BODY_MAX_BYTES` | Default `8192` (8 KiB). UTF-8 cap on an individual recorded payload/system message. Relevant when payload logging is enabled.                                                    |

### Host-side Docker and Hermes controls

These values affect the local task runner. They are **not** forwarded into the proxy container.

| Variable/template          | Meaning, default and guidance                                                                                                                                                                                                                       |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ENVIRONMENT_ID`           | Placeholder in every package script. Replace with the copied 1Password Environment ID. It is an identifier, not a secret and not an automatically expanded shell variable.                                                                          |
| `QODER_DOCKER_IMAGE`       | Default `qoder-proxy:local`. Image tag built and started by the Docker tasks. Use a tag you trust.                                                                                                                                                  |
| `QODER_CONTAINER_NAME`     | Default `qoder-proxy`. Managed container name. Existing containers without the management label are never overwritten.                                                                                                                              |
| `QODER_HOST_PORT`          | Default `3000`; valid 1–65535. Mac loopback port published to container port 3000. Changing it changes the default Hermes proxy URL too.                                                                                                            |
| `QODER_PROXY_BASE_URL`     | Default `http://127.0.0.1:QODER_HOST_PORT/v1`. Optional override for checks/Hermes. The helper accepts loopback HTTP URLs only; use an SSH tunnel for remote access.                                                                                |
| `QODER_HERMES_MODEL`       | Default `auto`. Qoder model identifier used for the test/chat profile. It must be a model supported by the proxy and your Qoder account.                                                                                                            |
| `QODER_HERMES_HOME`        | Interactive chat default `~/.hermes-qoder-proxy`. Separate Hermes profile location; use an absolute path if overriding. The test always uses a disposable profile.                                                                                  |
| `OP_SERVICE_ACCOUNT_TOKEN` | Optional 1Password host authentication credential for deliberately configured unattended use. Not needed with desktop integration. Never passed to Docker or Hermes, never committed, never stored inside the Environment it is intended to unlock. |

Positive numeric limits are validated on server startup. A typo causes a startup failure rather than silently disabling a limit. Start with the defaults, confirm `proxy:check` and `hermes:test`, then tune one variable at a time.
